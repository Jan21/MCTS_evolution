  benchmark.py                      ← benchmarking pipeline

Understand the key APIs before writing any code:
  GridEnv.propose_subgoal_states(state, support_robot=None)
    → returns list of (Subgoal, score) candidates for an open segment
  GridEnv.subgoal_score(subgoal)
    → heuristic: sum of 3 shortest path components
  GridEnv.compute_exact_shortest_path_length(start, end, support_pos=None)
    → exact SPL without dependent edges (used for fixed segments)
  GridEnv.compute_relaxed_shortest_path_length(start, end, support_pos=None)
    → relaxed SPL with dependent edges (used for open segment cost estimates)
  PartialPlan.open_edges()   → list of open (unresolved) segments
  PartialPlan.is_complete()  → True when no open segments remain
  PartialPlan.cost()         → sum of all segment costs

════════════════════════════════════════════════════════════════════════════════
 VARIANTS TO EXPLORE — STARTING IDEAS (NOT EXHAUSTIVE)
════════════════════════════════════════════════════════════════════════════════
The ideas below are STARTING POINTS. Once through these, you MUST continue:
search for new strategies, think of combinations, or invent new ones. The goal
is a broad landscape, not just these few.

── 1. GREEDY BEST-FIRST ──────────────────────────────────────────────────────
The simplest A* baseline. Use a priority queue of partial plans ordered by
total plan cost. At each step:
  1. Pop the lowest-cost partial plan
  2. Pick an open segment
  3. Call propose_subgoal_states() to get candidate subgoals
  4. For each candidate, create a new partial plan with the subgoal applied
  5. If the plan is complete, record it; otherwise push back to queue
  6. Prune any partial plan whose cost exceeds the best complete plan

Key decisions: how to pick WHICH open segment to expand first, how to score
candidates (use subgoal_score? raw relaxed SPL? weighted combination?).
Explore: different open-segment selection strategies (deepest-first,
cheapest-segment-first, most-constrained-first).

── 2. MULTI-HEURISTIC A* ─────────────────────────────────────────────────────
Try different heuristic formulations for ordering the open list:
  h1: sum of relaxed SPL for all open segments (current subgoal_score)
  h2: max of relaxed SPL across open segments (bottleneck heuristic)
  h3: weighted sum with plan depth penalty: cost + α * depth
  h4: number of open segments as tiebreaker

Compare h1-h4 on the same environments to see which heuristic matters most.
The heuristic doesn't just affect speed — it affects which complete plan is
found first, and thus the quality of the pruning bound.

── 3. BEAM SEARCH ─────────────────────────────────────────────────────────────
Keep only top-K partial plans at each expansion level:
  - Expand all plans at current depth
  - Score all resulting children
  - Keep only the K best
  - Repeat until a complete plan is found

Explore: beam width K (5, 10, 50, 100), scoring function, whether to keep
completed plans outside the beam.

── 4. ITERATIVE DEEPENING / BOUNDED A* ────────────────────────────────────────
Set a cost bound. Run A* but prune any plan exceeding the bound. If no
complete plan is found, increase the bound and restart. This controls memory
usage and can find solutions faster for easy instances.

Explore: initial bound (relaxed cost of root), bound increment strategy,
combining with different heuristics from variant 2.

── 5+ BEYOND THE LIST — REQUIRED ──────────────────────────────────────────────
After working through the starting ideas, CONTINUE exploring. Do not stop.
Ideas to pursue:

  SUBGOAL ORDERING: Different strategies for which open segment to resolve
    first — most constrained, cheapest, random.
  LOOKAHEAD: Before committing to a subgoal, estimate the cost of the
    sub-problems it creates (two-level lookahead).
  RESTARTS: Run the search multiple times with different random tiebreaking
    and take the best result.
  HYBRID: Combine beam search with A* pruning. Or use greedy for initial
    bound, then run full A* with that bound.
  ENVIRONMENT-ADAPTIVE: If you notice some environments are easy (few
    subgoals needed) and others hard (many dependencies), try a variant
    that adapts its strategy based on problem structure.
  SUBGOAL FILTERING: Before expanding, filter candidate subgoals more
    aggressively (e.g., skip subgoals with unreachable segments).

The starting list is a scaffold. The research session is not complete until
you have gone meaningfully beyond it.
