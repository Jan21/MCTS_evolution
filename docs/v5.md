# MCTS V5 — Nested Two-Stage (Skeleton + Realization)

## Overview

V5 separates the search into two levels. The **outer MCTS** searches over plan **skeletons** — high-level subgoal assignments that define the plan structure. The **inner search** takes a complete skeleton and attempts to **realize** it: computing exact shortest paths for all edges and detecting conflicts. Conflicts discovered by the inner search feed back as constraints on the outer search, guiding it toward skeletons that are actually realizable.

This clean separation avoids mixing strategic decisions (which subgoals to use) with tactical ones (can these segments coexist).

## What Changed from V1/V2

V5 shares V1's plan-building helpers but adds:

1. **Outer MCTS nodes** (`OuterNode`) with skeleton signatures and conflict constraint sets
2. **Inner realization pass** (`_realize_skeleton`) that closes all edges and reports conflicts
3. **Conflict feedback loop**: inner conflicts are recorded globally and penalize future outer expansions
4. **Skeleton caching**: identical skeletons (by signature) reuse inner evaluation results
5. **Inner SPL cache**: `compute_exact_shortest_path_length` results cached across all inner evaluations

## Key Concepts

### Skeleton Signatures

Each outer node tracks a `skeleton_sig` — a frozenset of subgoal assignment tuples:

```python
frozenset of (bottleneck_pos, support_pos, helper_color, parent_support_pos)
```

This enables transposition detection (same skeleton reached via different expansion orders) and conflict matching.

### Inner Realization (`_realize_skeleton`)

Given a complete skeleton (all subgoals assigned, but edges potentially open):

1. Process open edges in **topological order** (leaves toward goal)
2. For each open edge, attempt to close it:
   - Try independent path (`compute_exact_shortest_path_length(start, end, None)`)
   - For bottleneck parents, try dependent path through sibling support
3. If an edge is **unrealizable** (no path exists):
   - Extract a **conflict set**: the subgoal assignments responsible for the failure
   - Abort and return `(plan, None, conflict_set)`
4. If all edges close: return `(plan, cost, empty_set)`

**Inner pruning**: if the running cost of fixed edges exceeds the best known complete plan cost, abort early.

**SPL cache**: All `compute_exact_shortest_path_length` calls go through `_cached_spl`, which stores results in a shared dict keyed by `(start, end, support_pos)`. Since this function is deterministic, the cache is valid across all inner evaluations.

### Conflict Feedback (Inner to Outer)

When the inner search reports a conflict set `{sg_A, sg_B}`, V5:

1. Records it in a **global conflict library** with a count of how many times it's been observed
2. **Propagates** the conflict to all ancestor nodes of the current outer node
3. During future outer expansions, candidates are **penalized** proportionally to how many known conflicts they would trigger:

```
penalty = conflict_penalty_weight * count_of_matching_conflicts
```

This steers the outer search away from skeleton combinations that have been proven unrealizable.

### Outer Rollout

The outer rollout is a **greedy skeleton completion** followed by inner evaluation:

1. For each remaining open segment, pick the subgoal with the best score (penalized by known conflicts)
2. Pass the complete skeleton to `_realize_skeleton`
3. If realizable, return the exact cost. If not, record the new conflict and return penalty.

### Skeleton Pruning

If `skeleton_pruning` is enabled, partial skeletons whose relaxed cost already exceeds the best realized cost are skipped during expansion. This prevents the outer search from wasting time on skeletons that can't improve on the current best.

### Skeleton Cache

Identical skeletons (same `skeleton_sig`) share inner evaluation results. If a skeleton has already been realized (successfully or not), the cached result is returned immediately without re-running the inner search.

| `inner_spl_cache`         | true    | Cache exact shortest path length computations        |

## Trade-offs

**Advantages over V1-V4:**
- Clean separation of concerns — strategic (which subgoals) vs. tactical (can they coexist)
- Inner search provides **precise** conflict information based on exact computations, not heuristics
- Conflict sets enable strong pruning of the outer skeleton space
- Inner SPL caching is simple and highly effective (deterministic, context-free)
- Skeleton caching avoids redundant inner evaluations
- Achieved the best average cost (8.90) in benchmarks, including a uniquely optimal solution on env_6

**Costs:**
- Most computationally expensive per rollout — each outer rollout requires a full inner evaluation
- Fewer total plans found (42 vs 400+) due to the per-rollout overhead
- Conflict sets may be too specific (a conflict between two particular subgoals doesn't automatically generalize)
- Inner local repair is currently limited to path alternatives already available via `_try_close_edge`; more sophisticated repair (e.g., support robot swapping) is not yet implemented
