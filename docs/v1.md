# MCTS V1 — Contextual Plan-Refinement

## Overview

V1 is the baseline MCTS algorithm for solving Ricochet Robots puzzles via plan-space search. Instead of searching over move sequences, it builds and refines a **partial plan DAG** — a decomposition of the problem into subgoals. Each MCTS iteration selects, expands, and evaluates plan refinements until a complete (all edges fixed) plan is found.

## Core Idea

The algorithm starts with a single open edge from the goal to the target robot's initial position. At each iteration it:

1. **Selects** a promising tree node using LCB (Lower Confidence Bound — UCB adapted for cost minimization).
2. **Expands** the node by picking the highest-cost open edge and inserting a subgoal (bottleneck + support + helper leaf) to refine it.
3. **Rolls out** a random greedy completion to estimate the plan's total cost.
4. **Backpropagates** the cost up the tree.

Complete plans found during expansion or rollout are evaluated exactly and the best is tracked globally.

## Key Components

### MCTSNode

Each tree node holds:
- `plan` — a `PartialPlan` DAG snapshot
- `parent` / `children` — tree structure
- `action` — the subgoal action that created this node
- `visit_count`, `total_cost` — statistics for UCB

### Selection (LCB)

Uses Lower Confidence Bound for minimization:

```
LCB(child) = avg_cost - C * sqrt(log(parent_visits) / child_visits)
```

Children whose plan cost already exceeds the best known solution are pruned from selection. Progressive widening controls the branching factor: a node can have at most `C * N^alpha` children (default `C=2, alpha=0.5`).

### Expansion

Picks the open edge with the highest relaxed cost (the most "uncertain" segment). Generates candidate subgoals via `propose_subgoal_states`, filters out those that would create cycles (bottleneck position already appears in ancestors), and applies the best untried candidate.

After inserting a subgoal, all open edges are checked for direct closure — if a child can reach its parent via an exact independent or dependent path, the edge is fixed immediately without further decomposition.

### Rollout

Random greedy completion of the plan:
1. Close all directly closeable edges.
2. Pick a random open edge.
3. Generate candidates, sort by score, randomly pick from the top half.
4. Apply the subgoal and repeat (up to `max_rollout_depth` steps).

If the rollout produces a complete plan, it is evaluated exactly. Otherwise the relaxed cost estimate is returned.

### Fallback

If no complete plan is found after all iterations, the algorithm takes the tree node with the best average cost and greedily completes it by always picking the lowest-score candidate.

## Configuration (`conf/v1.yaml`)

| Parameter          | Default | Description                                    |
|--------------------|---------|------------------------------------------------|
| `max_iterations`   | 50      | Number of MCTS iterations                      |
| `ucb_exploration`  | 1.41    | Exploration constant (sqrt(2))                 |
| `pw_C`             | 2.0     | Progressive widening coefficient               |
| `pw_alpha`         | 0.5     | Progressive widening exponent                  |
| `max_rollout_depth`| 30      | Max subgoal insertions per rollout             |
| `penalty_cost`     | 1000.0  | Cost assigned to failed expansions/rollouts    |

## Limitations

- **No inter-segment awareness**: Each subgoal is evaluated independently. When two segments require the same helper robot at different positions, V1 doesn't detect this conflict until final evaluation (if at all).
- **Greedy edge selection**: Always refining the highest-cost open edge may miss cases where a lower-cost edge is actually the bottleneck for plan feasibility.
- **No conflict-driven exploration**: The UCB formula treats all nodes equally regardless of potential helper-reuse conflicts lurking in the plan.

These limitations motivate V2's conflict graph extension.
