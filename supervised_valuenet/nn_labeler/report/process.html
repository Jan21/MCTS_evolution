NN Labeler: replacing the exact solver for data labeling across grid sizes

Ricochet Robots planner study · process report · started 2026-07-31 · local document, updated as milestones land. Every number traces to a named file in the repo.

1. The problem

All training data in this study is labeled by exact solvers, and the exact solvers do not scale. Two measured walls (sources: FINDINGS.md §30–34, bench meta sidecars):

  • Backward (subgoal) labels price every candidate at every decision with a full plan-space A* solve. The extended-vocabulary label campaign as first configured projected ~441 node-hours (against ~879 then remaining) — on the Rust engine at 16 threads, i.e. with no faster implementation left. Capping solver iterations rescued the cost (~5 nh) but depleted exactly the candidate type the labels exist to teach (by-reference share 13.5% → 4.8%; the retrain then lost −24.6 points on the frontier). Cost rises along the grid axis: median legitimate-rollout iterations 170–253 (16×16) → 465 (24×24) → 1,062 (32×32).
  • Forward labels and benchmark grading use a move-space A* whose state space is (G²)R. At fixed caps its failure rate is 0% (16×16, 4 robots) → 29.8% (6r) → 40.9% (8r) → 48.4% (24×24/4r) → 64.2% (24×24/8r) → 61.1% (32×32/4r).

The owner's goal: train a neural network that generalizes across grid sizes, then walk up the ladder (17×17, 18×18, … 32×32) generating labeled data with the net. Debug the whole pipeline on small boards (8×8) first. One GPU at a time, small experiments before big ones, ≤16 h walltimes (data-center cooling regime).

2. What made this feasible (research pass, 2026-07-31)

  • The nets were one tensor away from size-invariance. The backward value net is a weight-tied looped transformer over per-cell tokens with slide-graph-masked attention; its only grid-locked weight is a learned absolute positional embedding of shape [G²+1, 192] (train/looped_pc.py:146). Everything else — encoder, the ~741k-parameter looped block, readout — is size-agnostic.
  • Zero-shot transfer already worked once: base-trained (16×16/4r) nets ran unchanged on 6- and 8-robot boards and were slightly better than per-config nets (FINDINGS §29). Retraining on same-size data repeatedly hurt (§34, §47) — evidence favoring a train-once approach.
  • Verifiability: a completed backward plan can be realized to a real move sequence and replayed through pure physics (eval/realize.py::strict_moves, simulate.py). NN-produced labels never need to be trusted — they can be certified playable, and their optimality gap audited wherever the exact solver still works.
  • Board generation is size-generic (RR_GRID env; walls scale as round(48·(G/16)²)); the Rust labeling engine is size-parametric to n≤64.

5. The certified-descent labeler

nn_labeler/descent.py — the engine of Plans B/C. At each decision it enumerates candidates exactly as the exact labeler does (same propose, same top-14 score truncation), but prices each candidate by greedy NN completion instead of an exact solve: commit the candidate, then repeatedly take the value net's best-scored next candidate (keeping the exact-shortest-path fast path, and pruning with the proven prefix_playable check) until the plan completes. The completed plan is realized under full physics; only candidates whose completion actually plays out are labeled. Labels are certified upper bounds in the exact labeler's own plan-cost units; is_optimal = argmin of certified bounds. Records keep the frozen 18-field schema plus provenance (n, label_source, ctg_certified, label_model, label_model_sha) so they are drop-in for the existing trainers and can never be silently confused with exact labels.

done

Plumbing validated at 8×8 with a deliberately weak 1-epoch net: 6/8 RNG instances kept, 11/12 corpus-replay instances kept, ~0.3–0.8 s/instance on CPU. The label-comparison tool (nn_labeler/audit_descent.py) passed an identity self-audit (3040/3040 groups, 20,000/20,000 candidates, all gaps zero) and, against the weak net's labels: zero negative gaps (upper-bound property holds), and on exact-optimal candidates the weak net's completions were exactly optimal 93% of the time (mean gap 0.20) — the structure (exact-pin fast path + candidate enumeration) carries much of the weight even before training. nn_labeler/results (session scratchpad copies); sidecar manifests.
