Predicting the move, and the moves‑to‑go

A neural net learns to solve a sliding‑robot puzzle by predicting, for any board, how many moves are left and which move to play — then searching with those two predictions. It is trained first from a perfect solver, then from its own solving, with no solver at all.

    What this is

    A neural net learns to solve Ricochet Robots — the sliding‑robot puzzle above. For any board it predicts two things:

    value

    How many moves are left to the goal (the shortest count). Also called cost‑to‑go.

    policy

    Which move to play next — which robot, which direction.

    A search called NN A* uses both: the policy suggests a few moves worth trying, the value scores where they lead. The net is trained first from a perfect solver (called supervised), then taught to improve from its own solving, with no solver at all (called self‑play).

    How to read this page. This Overview is the whole story in plain English. The Details tab is the full method — architecture, data pipeline, search, training, results. The Glossary defines every term; start there if a word is unfamiliar.

    details · architecture · pipeline · results

    The move-based planner, in full

    One board state, one two-headed network, one search. This tab walks the whole stack — the reformulation, the net, the data and its three labelling lanes, the search loop, expert iteration, the five models, the numbers, and the dead ends — each stated once.

    01 — the reformulation

    From subgoal DAGs to primitive moves

    The old system searched over plans built from sub-targets. The new one searches over board states, one primitive move at a time.

    Before · subgoal DAGs

    Search ran over partial plans assembled from sub-targets (bottleneck, support, helper). A node was a plan fragment; cost was a weighted count of subgoals.

    After · primitive moves

    Search runs over board states. A node is the full 4-robot position; an edge is one robot sliding until it hits a wall or robot; cost is moves.

    Moves are the unit
    Cost = number of slides. The objective is exactly what the puzzle asks for, so labels and regret are in one honest unit.
    States are Markov
    A board fully determines its future; history is irrelevant. Every state can be labelled independently — no trajectory context needed.
    Labels are exact
    An oracle A* gives each state its true cost-to-go (d* − depth), so supervision is exact rather than heuristic.
    02 — the network

    One shared encoder, two heads

    Every board becomes node features plus slide-graph attention masks; a weight-tied encoder produces token embeddings that feed a value head and a policy head.

    Input · per board
    Node features [257,14] — 256 cells + 1 global token. Channels: ch0-3 per-color robot occupancy · ch4 target-robot cell · ch5 goal cell · ch6-13 slide-displacement fields. Plus slide-graph attention masks A_all / A_ind [257,257].
    ↓
    Shared encoder
    Linear 14→192 + learned positional embed, then a weight-tied LoopedLayer ×12. Each layer attends over the global token, an A_all-masked pass, and an A_ind-masked pass.
    ↓token embeddings split to two heads

    Value head

    [global-token ⊕ goal-cell ⊕ target-robot-cell] → HL-Gauss over 64 cost-to-go bins. Value = the expected bin. Predicting a distribution over move-counts trains more stably than regressing a single number.

    Policy head

    Per (robot, dir): [robot-cell-emb ⊕ slide-destination-cell-emb] → a 4×4 grid of logits, masked to legal moves.

    Why the policy reads the destination cell. Picking the optimal move is a 1-step lookahead — if this robot slides, where does it stop, and does the move-count drop? A static per-robot readout can’t do it and won’t even overfit (top-1 ≈ 0.10). Feed each move’s slide-destination cell embedding and the same head reaches 0.96.
    Loss
    HL-Gauss value cross-entropy + policy_weight · masked-policy cross-entropy.
    03 — the data pipeline

    One pipeline, three labelling lanes

    Boards, splits and instance generation are shared. Only how states get labelled differs — and all lanes emit one record schema, so the dataset and loss code are reused verbatim.

    Boards & splits

    Boards from gen_grids (env_{id}.pkl). Splits: train 1000-1599 · val 1800-1999 · test 2400-2599.

    Instance generation

    Supervised / candidate: sample 4 random robots + a random target robot and cell, keep if reachable (a cheap admissible filter, not an oracle solve). Self-play: target-biased forward-walk (random board, slide the target robot k~U(1,16) times, relabel goal = target’s final cell → guaranteed solvable) + 25% raw random.

    The label branch — the crux. Same instance, three labellings:

    Lane A · supervised
    An exact oracle (perfect A* solver, train-time only) solves each instance and labels ONLY the states on ONE optimal path with their exact cost-to-go (d* − depth). Off-path states get no label.
    Lane B · candidate-scored
    Same on-path labels, PLUS for each state enumerate its legal candidate moves, apply each to get the child (resulting) state, solve THAT child exactly with the oracle, and emit a value-only record (best_moves=[], full=False) carrying the child’s own exact cost-to-go. Off-path children get exact labels.
    Lane C · self-play
    The net’s OWN budgeted A* (nn_astar, no oracle) solves forward-walk puzzles. On the solved path: value = T − j (remaining length), the committed move as policy, and a goal anchor (cost_to_go=0). Unsolved instances are dropped.

    All three lanes emit this identical record:

    {env_id, robots[[x,y]×4 in COLOR_ORDER], target[x,y], target_idx, cost_to_go, best_moves[[slot,dir]], legal_moves[[slot,dir]], depth, full}
    04 — search

    NN A*: the net drives best-first search

    A short primer first, then how the two heads slot into the search loop, then the honest caveat about optimality.

    A* primer

    A* is best-first search over board states. It keeps a frontier of states ranked by f = g + h, where g = moves made so far to reach that state and h = an estimate of moves still to go. It repeatedly pops the lowest-f state, expands it (generates the states its moves lead to), and never re-expands a state it has settled (the “closed set”). Classic A* uses an admissible (never-overestimating) h and returns optimal paths.

    NN A* sets h = the value head and, before expanding, uses the policy to keep only the top-k moves.

    1 · pop
    Pop the lowest-f state, f = g + value.
    ↓
    2 · goal test
    Is it the goal? Return g.
    ↓
    3 · expand
    Generate the ≤16 legal moves.
    ↓
    4 · policy prune
    Policy ranks the moves, keep top-k, grey out the rest.
    ↓
    5 · value score
    Value scores the k resulting (child) states.
    ↓
    6 · push
    Push each child with f = (g+1) + value(child); closed-set on state.
    ↓repeat
    Optimality is empirical, not guaranteed. The value head is learned and not admissible, and policy top-k pruning can discard optimal moves — so NN A*’s optimality is measured (as regret), not proven.
    Policy proposes, value ranks the proposals. That split is why the value head works inside search even though value-alone fails as a greedy controller — see the value-greedy number in the model cards and results.
    05 — self-play / expert iteration

    The net trains on its own search’s solutions

    A closed loop with net-solvability as the implicit curriculum — framed honestly about what it is and is not.

    generate
    Forward-walk puzzles (guaranteed solvable).
    →
    solve
    The net’s own budgeted A* solves them — no oracle.
    →
    train
    Train on the solved trajectories.
    →
    repeat
    Stronger net → deeper puzzles solved.
    Net-solvability is the curriculum
    The net solves shallow puzzles first, learns from them, then reaches deeper ones — the deep-state share of the data climbs each round.
    Honest framing. (1) This is single-agent Expert Iteration with an A* expert (DeepCubeA lineage), NOT AlphaZero/MCTS — there is no MCTS, no PUCT, no visit-count targets; “self-play” here means the net trains on its own search’s solutions, not adversarial self-play. (2) The value target T−j is the length of a possibly-suboptimal found plan, so it is biased slightly high — but it is a pure Monte-Carlo return with no bootstrapping, which sidesteps the usual value-iteration instability.
    Warm-start
    Fine-tune the supervised net.
    From-scratch
    Random init, no oracle anywhere.
    06 — the five models

    What each model trains on, and what it buys

    Same net and search throughout; the models differ only in their labels.

    Original subgoal system

    Plans, not board states. Searches over partial plans made of sub-targets (bottleneck / support / helper).

    Cost is a weighted subgoal count (helper steps count 2), not moves.

    So its 99.6% is in a different unit — not directly comparable. Checkpoint not kept.

    Supervised baseline

    The baseline. The oracle labels the shortest path only.

    Learns cost-to-go and the optimal move on-path: 85% · regret 0.354 · value-MAE 0.263 · policy top-1 0.960.

    Weakness = off-path value (value-greedy 7%).

    Candidate-scored best

    Still supervised, but the oracle also grades every candidate’s resulting (off-path) board — the value net finally sees off-path.

    100% · regret 0.067 · value-greedy 7% → 78%.

    Uses the oracle at train time only; pure NN at inference.

    Self-play warm

    The net’s own A* replaces the oracle; from the supervised net, one iteration.

    97.6% · regret 0.055 · value-greedy 7% → 51%.

    Off-path coverage comes from visited states, no oracle.

    Self-play from scratch the goal

    Random init, no oracle ever; 16 iterations.

    87.6% · regret 0.213 (iter14 89.1%).

    Honestly: this matches / edges past supervised (85%) at substantially higher compute, single run. The decisive model is candidate-scored.

    Candidate-scored vs self-play. Both fix off-path value coverage. Candidate-scored uses the oracle on extra states — exact, one pass, still supervised. Self-play uses the net’s own A* on the states it visits — approximate, iterative, no oracle.

    08 — what went wrong

    The dead ends, kept in the record

    Four things that failed or were rejected, and what fixed each.

    reverse-scramble curriculum — failed
    DeepCubeA’s trick assumes reversible moves; Ricochet slides aren’t, so scrambled starts stay ~1 move from goal (measured ~1.3 even at depth 16). The net never trained deep → capped 66%. Fixed with forward-walk.
    ↓
    value-target bug — downward ratchet
    min(found_length, net_estimate) dragged labels toward the net’s own wrong belief (a partial bootstrap). Fixed to plain found length.
    ↓
    under-training a random net
    Fine-tune settings on a random init gave a weak policy. Fixed to supervised-grade (lr 3e-4, policy_weight 1.0).
    ↓
    rejected: oracle fallback at inference
    Would guarantee 100% but isn’t the NN — removed. The planner is pure NN.

    glossary · the puzzle

    The game, and what the net predicts

    termplain English
    robot / target robotFour robots slide on the board. One of them — the target robot — is the one that must reach the goal.
    move (slide)Pick a robot + a direction; it slides until a wall or another robot stops it. Each move costs 1.
    goal / target cellThe single cell the target robot has to land on.
    optimal / shortestUsing the fewest possible moves. The optimal path is a shortest solution (there can be more than one).
    board state (“state”)A snapshot: where the four robots sit right now. The net sees only the snapshot, not how you got there (that property is called Markov).
    value (cost‑to‑go)One of the net’s two predictions: its estimate of how many moves are left to reach the goal from a board. Smaller = closer. The same quantity is also called moves‑to‑go or remaining length.
    policyThe net’s other prediction: a ranking of which move to play from a board (over robot × direction).
    glossary · paths & search

    Boards, moves, and the planner

    termplain English
    on‑path stateA board you pass through on a shortest solution. (See the picture above.)
    off‑path stateA board reached by a move that is not part of any shortest solution — a detour or wrong turn.
    candidate (move)Any legal move you could make from a board. The search “considers the candidates.”
    resulting state / childThe board you get after making a candidate move.
    NN A* (the planner)The search that actually solves puzzles at run time. Repeatedly: take the most promising board, try its best few moves, continue until the target arrives. “Promising” = smallest (moves so far + value).
    policy proposes,
    value ranks    		How the two heads combine in NN A*: policy narrows to the few moves worth trying, value scores the boards they lead to. Together they beat either head alone.
    top‑kKeep only the k best moves the policy proposes at each step; prune the rest.
    value‑greedyA stripped‑down planner using only value (no policy): step to whichever neighbouring board value likes best. It fails badly (~7% solved) precisely because value is unreliable off‑path — which is why value‑greedy’s solve rate is used as the test for off‑path value quality.
    policy‑greedyThe opposite stripped‑down planner: play only the policy’s single top move each step, no search.
    glossary · search machinery

    A* and its vocabulary

    The search words. If f = g + h looked cryptic in the Details tab, this is for you.

    termplain English
    A*A classic best-first search: always work on the most promising unexplored board first, judged by cost-so-far plus an estimate of what’s left.
    best-firstAt each step, expand whichever option currently looks cheapest overall — not depth-first, not breadth-first.
    gMoves made so far to reach a board (the known cost).
    h (heuristic)An estimate of the moves still to go. In NN A*, h = the value net’s prediction.
    f = g + hThe score A* ranks boards by: known cost so far + estimated cost to finish. It always pops the smallest f.
    expandGenerate the boards reachable from the current one by one legal move each.
    closed setBoards already settled; A* won’t re-open them (Ricochet boards are Markov, so each need be handled once).
    frontier / priority queueThe pool of discovered-but-not-yet-expanded boards, kept ordered by f.
    admissibleA heuristic that never over-estimates. Admissible h makes classic A* return a true shortest path — the learned value net is not admissible, which is why NN A* is optimal only empirically.
    Monte-Carlo returnA value target read off an actual solution the search found (its length), not a bootstrapped guess. Self-play uses this.
    MCTS / PUCTThe tree search + selection rule behind AlphaZero. Not used here — a single-agent puzzle with a cost-to-go value is handled more simply by A*.
    expert iteration (ExIt)Train the net to match a stronger search (the “expert”), then use the improved net to power the next round’s search. Repeat — this is what “self-play” means here.
    subgoal DAG (the old system)The older approach searched over partial plans made of sub-targets (bottleneck / support / helper), not board states, with a different weighted cost unit.

    glossary · training

    How the models are trained

    termplain English
    oracleA perfect but slow exact solver. Used only to create training answers and to grade at test time — the deployed planner never calls it.
    supervisedTrain the net on the oracle’s exact answers (the baseline approach).
    candidate‑scoredA supervised add‑on: also have the oracle grade every candidate’s resulting board, so the value net finally sees off‑path boards too. Still uses the oracle only at training time.
    self‑play / expert‑iteration (ExIt)No oracle. The net solves puzzles with its own search, trains on its own solutions, and repeats — getting better each round.
    warm‑start vs from‑scratchSelf‑play started from the trained supervised net (warm) versus from a random net (from scratch — no oracle involved anywhere).
    forward‑walkHow self‑play makes solvable practice puzzles: take a board, slide the target robot a few random times, then call wherever it landed “the goal.” A ready‑made solution comes for free.
    iteration (iter)One round of self‑play: generate puzzles → solve → train → repeat. “iter14” = after 14 rounds.
    glossary · under the hood

    Net internals — only if you care

    termplain English
    encoder (looped transformer)The shared front part of the net that reads the board, before it splits into the value head and the policy head.
    node features [257,14]How a board is fed to the net: 256 cells + 1 summary token, each described by 14 numbers (robot positions, goal, slide directions).
    cost‑to‑go bins / HL‑GaussThe value is output as a probability spread over the possible move‑counts (0–63) instead of one bare number — it trains more stably.
    destination (slide) lookaheadThe policy reads, for each move, the cell the robot would stop on. That one‑step peek is what lets it learn good moves at all (without it, accuracy collapses to ~10%).
    admissible heuristicA never‑overestimating distance guess. The oracle uses one to solve exactly and fast; it is not the learned value net.
